# Public API — read paths, write paths and Document

Package `snd`'s current public surface, for reading a MUGEN/Ikemen GO
`.snd` v1 or v2 file and decoding its audio to raw PCM.

## v1 read path

## `ParseV1`

```go
func ParseV1(r io.ReaderAt) (*V1SoundTable, error)
```

Reads a v1 file's header and sound table from `r`. Each entry's audio data
is located (file offset and length) but not decoded yet — call
`DecodeV1Sound` for that.

**Errors:** a short read on the header or a sound subheader, a bad
signature, a negative declared sound count, or the sound table ending
before the declared count is reached, all return a descriptive `error`
wrapping the underlying I/O error where relevant. `ParseV1` never panics on
malformed input.

## `V1SoundTable` / `V1Header` / `V1SoundEntry`

```go
type V1Header struct {
	Version        [4]byte
	NumberOfSounds int
}

type V1SoundEntry struct {
	Group  int
	Sample int
	Offset int64
	Length int
}

type V1SoundTable struct {
	Header V1Header
	Sounds []V1SoundEntry
}
```

Pure data — no I/O. `Offset`/`Length` locate a sound's embedded RIFF/WAVE
audio blob in the source file.

### `(*V1SoundTable) Index`

```go
func (t *V1SoundTable) Index(group, sample int) (int, bool)
```

Resolves a `(group, sample)` key to its position in `t.Sounds`. Returns
`false` if no such sound exists in the table — this is how a caller checks
whether a sound reference is valid before decoding it.

## `DecodeV1Sound`

```go
func DecodeV1Sound(r io.ReaderAt, table *V1SoundTable, group, sample int) (*DecodedSound, error)
```

Reads and decodes the embedded audio for the sound entry keyed by
`(group, sample)`. The entry's embedded audio must be a RIFF/WAVE blob
carrying uncompressed PCM — 8-bit unsigned or 16-bit signed, the two
depths real `.snd` files use.

**Errors**, each naming the `(group, sample)` entry:
- the key is not in `table`
- reading the entry's audio bytes fails (truncated file)
- the blob is not a valid RIFF/WAVE container
- the `fmt` or `data` chunk is missing or truncated
- the WAVE format tag is not PCM (see the ADPCM note below)
- the bit depth is neither 8 nor 16

`DecodeV1Sound` never panics on malformed input — every failure mode above
returns an `error`, never a wrong or partial `DecodedSound`.

## `DecodedSound`

```go
type DecodedSound struct {
	SampleRate    int
	Channels      int
	BitsPerSample int
	PCM           []int16
}
```

`PCM` is interleaved by channel and always normalized to signed 16-bit,
regardless of the source's original bit depth: 8-bit unsigned samples are
re-centered around zero and scaled up to use the full `int16` range.
`BitsPerSample` still reports the *original* source depth (8 or 16), for
callers that care.

## ADPCM is out of scope

`DecodeV1Sound` only decodes PCM. A scan of 496 real, unmodified community
`.snd` files (54,306 sound entries) found zero ADPCM-encoded entries, and
Ikemen GO's own current sound loader itself only accepts PCM too — so no
`.snd` file this library targets could rely on ADPCM playing correctly
either way. See `.vibe/decisions/001-v1-pcm-only-decode-adpcm-out-of-scope.md`
for the full reasoning. An ADPCM entry decodes to a descriptive error
(unsupported format tag), never silently wrong audio.

## v2 read path

`.snd` v2 adds one behavioral extension over v1: a sound entry can point at
an external audio file instead of embedding its samples. The on-disk
subheader layout itself (`Group`/`Sample` each a 4-byte field) is identical
between v1 and v2 — see decisions `002` and `005` below for why, and for the
real-file evidence behind it.

### `ParseV2`

```go
func ParseV2(r io.ReaderAt) (*V2SoundTable, error)
```

Reads a v2 file's header and sound table from `r`, the same way `ParseV1`
does for v1. Same error shape: a descriptive `error`, never a panic, on a
short read, bad signature, negative sound count, or a table ending early.

### `V2SoundTable` / `V2Header` / `V2SoundEntry`

```go
type V2Header struct {
	Version        [4]byte
	NumberOfSounds int
}

type V2SoundEntry struct {
	Group  int
	Sample int
	Offset int64
	Length int
}

type V2SoundTable struct {
	Header V2Header
	Sounds []V2SoundEntry
}
```

Same shape as v1's types; `(*V2SoundTable) Index(group, sample int) (int, bool)`
resolves a key the same way `V1SoundTable.Index` does. See
`.vibe/decisions/002-v2-subheader-uses-4-byte-group-and-sample-fields.md` and
`.vibe/decisions/005-v1-group-sample-fields-are-4-bytes-not-2.md` for why v1
and v2's on-disk subheader layouts turned out to be identical.

### `DecodeV2Sound`

```go
type ExternalAudioOpener func(path string) ([]byte, error)

func DecodeV2Sound(r io.ReaderAt, table *V2SoundTable, group, sample int, openExternal ExternalAudioOpener) (*DecodedSound, error)
```

Decodes the sound keyed by `(group, sample)`, same PCM-only contract as
`DecodeV1Sound`. If the entry's payload is embedded audio, `openExternal` is
never called and may be `nil`. If the payload is instead an Ikemen GO
external-file-reference (a relative path, e.g. `"sfx/hit1.wav"`) — detected
because it is not a valid RIFF/WAVE blob but is a plausible, printable path
ending in a recognized audio extension — `openExternal(path)` is called to
get that file's bytes, which are then decoded the same way.

This package never opens a file or makes a network call itself: resolving a
path (relative to a directory, inside a bundled archive, from a preloaded
map, ...) is entirely `openExternal`'s job, which keeps this package usable
from a WebAssembly build with no real filesystem. See decision
`.vibe/decisions/003-v2-external-file-reference-detection-and-resolution.md`.

**Errors**, each naming the `(group, sample)` entry (and the external path,
when relevant):
- the key is not in `table`
- reading the entry's payload fails (truncated file)
- an external reference has no `openExternal` (nil)
- `openExternal` fails (file not found, read error, ...) — wrapped, so
  `errors.Is`/`errors.As` reach the underlying cause
- the resolved external file is not WAV/PCM (only WAV/PCM external files are
  supported — see decision `003`)
- any of `DecodeV1Sound`'s own embedded-audio error cases (bad RIFF/WAVE,
  missing chunks, unsupported format tag or bit depth)

## Version-agnostic decode

### `DecodeSound`

```go
func DecodeSound(r io.ReaderAt, group, sample int, openExternal ExternalAudioOpener) (*DecodedSound, error)
```

Reads a `.snd` file from `r` — v1 or v2, auto-detected from the file's own
header, the same way a caller no longer has to choose between `ParseV1`
and `ParseV2` themselves — and decodes the sound keyed by
`(group, sample)`. `openExternal` is passed straight through to
`DecodeV2Sound` when `r` turns out to hold a v2 file with an
external-file-reference entry; it is simply ignored for a v1 file, which
has no such extension.

This is the function `cmd/wasm`'s JS entrypoint (see
[docs/wasm.md](wasm.md)) exposes, so a JS caller doesn't need to detect the
version itself either — but it is equally usable from native Go code as a
convenience over calling `ParseV1`/`ParseV2` and the matching decode
function directly.

**Errors:** the same as `ParseV1`/`ParseV2` and `DecodeV1Sound`/
`DecodeV2Sound` — a bad signature, a truncated header, or any of the
version-specific decode errors documented above for whichever version was
detected. See
[`.vibe/decisions/004-wasm-entrypoint-api-shape-and-version-detection.md`](../.vibe/decisions/004-wasm-entrypoint-api-shape-and-version-detection.md)
for how version detection itself works.

## v1 write path

```go
func ReadV1Set(r io.ReaderAt) (*V1SoundSet, error)
func EncodeV1(set *V1SoundSet) ([]byte, error)

type V1SoundSet struct {
	Version       [4]byte
	HeaderPadding []byte // comment area between the header fields and the first subheader, written verbatim
	Sounds        []V1Sound
}

type V1Sound struct {
	Group  int
	Sample int
	Audio  []byte // embedded RIFF/WAVE blob, neither decoded nor validated
}
```

`ReadV1Set` loads a whole v1 file in memory without decoding audio.
`EncodeV1` writes it back: header, padding, then each subheader and audio
one after the other, the last subheader pointing at the end of the file.
A real unmodified file re-encodes byte-identical (496 real files checked).

**Errors:** `ReadV1Set` returns the `ParseV1` errors, plus a first
subheader overlapping the header and a file cut inside an audio blob.
`EncodeV1` refuses a nil set, a group or sample outside the signed 32-bit
range, and a file past 4 GiB. Duplicate keys and non-WAV payloads are
kept. See `.vibe/decisions/006-v1-write-path-layout-and-scope.md`.

## v2 write path

```go
func ReadV2Set(r io.ReaderAt) (*V2SoundSet, error)
func EncodeV2(set *V2SoundSet) ([]byte, error)

type V2SoundSet struct {
	Version       [4]byte // zero value = default stamp 2,0,0,0
	HeaderPadding []byte
	Sounds        []V2Sound
}

type V2Sound struct {
	Group        int
	Sample       int
	Audio        []byte // embedded RIFF/WAVE blob, or
	ExternalPath string // Ikemen GO external-file reference, never inlined
}
```

Same container layout as the v1 write path. `ReadV2Set` is lenient and
classifies each payload like `DecodeV2Sound` does. `EncodeV2` is strict: it
refuses a duplicate `(group, sample)`, an empty payload, a sound with both
`Audio` and `ExternalPath`, audio that is not RIFF/WAVE, an external path
that is not printable ASCII ending in a recognized audio extension, and a
version stamp whose first byte is not 2, plus what `EncodeV1` refuses. See
`.vibe/decisions/007-v2-write-path-validation-and-shared-container.md`.

## Document

```go
func ParseDocument(data []byte) (*Document, error)
func (d *Document) Len() int
func (d *Document) Sound(i int) (DocumentSound, error)
func (d *Document) SetPayload(i int, payload []byte) error
func (d *Document) Serialize() ([]byte, error)

type DocumentSound struct {
	Group   int
	Sample  int
	Payload []byte // a copy
}
```

A `.snd` file (v1 or v2: they share one layout) that writes back
byte-identical when untouched. It keeps the version bytes, the header
comment, the bytes between sounds, the bytes after the last sound, and what
each last pointer pointed at (end of file, zero, or a literal value).
`SetPayload` replaces one sound's payload; `Serialize` then changes only
that sound's entry and the offsets that must move. 496 real files
round-trip byte-identical.

**Errors:** `ParseDocument` returns the `ParseV1` errors, plus a payload
running past the end of `data`, a first subheader overlapping the header and
sounds not laid out in increasing order of offset ("unsupported layout").
`Sound` and `SetPayload` refuse an index out of range. `Serialize` refuses
a file past 4 GiB. See `.vibe/decisions/008-document-keeps-layout-and-pointer-kinds.md`.

## Editing sounds

```go
func (d *Document) Find(group, sample int) (int, bool)
func (d *Document) AddSound(group, sample int, wav []byte) error
func (d *Document) ReplaceSound(group, sample int, wav []byte) error
func (d *Document) RemoveSound(group, sample int) error
```

Edit a `Document` by `(group, sample)` key. Everything the edit does not
touch is kept byte for byte. `AddSound` appends after the last sound and
refuses a key already in the document. `ReplaceSound` and `RemoveSound`
refuse a key that is not there; when a real file holds the same key twice,
the first one is used.

**Audio rule.** `wav` must be a RIFF/WAVE blob of plain PCM, 8-bit or
16-bit, with at least one channel and a non-zero sample rate — exactly what
`DecodeV1Sound` and `DecodeV2Sound` read back. Anything else (ADPCM, 24-bit,
a broken file) is **refused, never converted**: converting needs a
resampler and codecs this stdlib-only library does not carry. A refused edit
leaves the document unchanged. The same three operations are exported to
JavaScript, see [wasm.md](wasm.md). See
`.vibe/decisions/009-editing-api-rejects-non-conformant-audio.md`.
