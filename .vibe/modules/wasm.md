# Module: wasm
**Role:** `cmd/wasm` is the library's WebAssembly entrypoint (backlog item 003): thin `syscall/js` glue exposing the root package's `DecodeSound` (see `modules/root.md`) to a browser or any JS host as a single global function, so `mode-quick-versus` can decode system/common sound sets directly, without a Go toolchain of its own and independent of `character`'s own WASM build — even though both ultimately wrap this same package. It carries no logic beyond argument conversion, calling into the root package, and marshaling results to JS — all real behavior lives there, unit-tested independently.
**Files:** `cmd/wasm/main.go`, `cmd/wasm/smoke.mjs`
**Exports (JS, not Go):**
- `globalThis.OpenKakutouSnd.decode(sndBytes, group, sample, resolveExternal)` — `sndBytes` a `Uint8Array` of a `.snd` file's raw bytes (v1 or v2, auto-detected); `group`/`sample` the sound key; `resolveExternal` an optional JS function `(path) => Uint8Array`, invoked *synchronously* via `js.Value.Invoke` to resolve a v2 external-file-reference entry (cannot be `async`/return a Promise — the caller must already hold the bytes); returns `{ sampleRate, channels, bitsPerSample, pcm: Int16Array|null, error: string|null }` (exactly one of `pcm`/`error` non-null)

**Depends on:** `modules/root.md` (`DecodeSound`, `ExternalAudioOpener`, `DecodedSound`)

**Design decision:** `main.go` is build-tag gated (`//go:build js && wasm`), so it is invisible to a normal host `go build ./...`/`go test ./...` — only `GOOS=js GOARCH=wasm go build ./cmd/wasm` compiles it. `decode` never lets an internal panic escape to the JS caller (a `recover()` at the callback boundary, and a second one inside the `resolveExternal` wrapper itself, both report failure as `error` instead) and never leaves the module in a broken state after an error — `mode-quick-versus` keeps one WASM instance alive for a whole session and calls `decode` repeatedly, so this matters more here than a one-shot script would care. Unlike sibling repo `sff`'s two-global surface (`load`/`resolveSprites`, one operation each), `.snd` only has one operation — decode a sound — so it gets exactly one JS-callable global, per the backlog item's own "a version-agnostic decode call" wording. Version detection reuses this repo's own already-established convention (`header[12] == 2` for v2 — see `modules/root.md`'s `DecodeSound`), not `sff`'s own byte offset, since the two file formats lay their version stamps out differently. `resolveExternal`'s synchronous contract is validated at the boundary: a non-function or a value that isn't a plain `Uint8Array` (e.g. a `Promise` a caller mistakenly passed an `async` function for) reports a descriptive error naming the exact expectation, rather than a confusing failure surfacing later from inside `js.CopyBytesToGo`. See `.vibe/decisions/004-wasm-entrypoint-api-shape-and-version-detection.md`. `smoke.mjs` is a Node.js verification harness (loads the built `.wasm` via `wasm_exec.js`, the same way a browser would) — it is not a `go test` file since `syscall/js` code cannot run under the plain Go toolchain, and doubles as a minimal JS usage example. See `docs/wasm.md`.
