# V2 external-file-reference entries are detected by a path-shaped payload heuristic and resolved through a caller-supplied opener; only WAV/PCM externals decode

**Context:** Backlog item 002 requires v2 support for "Ikemen GO's own extension where a sound table entry points at an external audio file (e.g. `.wav`/`.ogg`) instead of embedding samples." No authoritative binary specification for this extension could be found: it is absent from Ikemen GO's own current reference loader (`src/sound.go`, both `develop` and `release/1.0` — every entry's payload is read as `SubFileLength` raw bytes and fed straight to a RIFF/WAVE decoder, with no branch for an external path at all), from public web search, from Ikemen GO's own GitHub issues/wiki, and from a byte-level scan of the full local real-character corpus (497 files, `.vibe/fixture-sources.md`) — no file there declares itself version 2 in any conventional sense, and none contains an entry whose payload looks like anything other than embedded audio or corrupt data.

The backlog item's own acceptance criteria anticipate exactly this outcome, explicitly allowing "a clearly-marked synthetic fixture with the gap noted" when no real Ikemen GO character with this feature can be found — mirroring `sff`'s own accepted-gap precedent for RLE5 (`sff`'s decision `014`). Unlike RLE5, though, there is no reference *algorithm* to port here (RLE5's bit-unpacking logic did exist in Ikemen GO's source, just without a real fixture) — there is no runtime behavior to port at all, so this decision is a genuine design choice, not a port.

Two further constraints shape the design:
- This package must stay playback-free and WASM-safe (`CLAUDE.md` design constraint 1) and cannot assume a real filesystem is reachable the way `os.Open` would need — a browser `snd.wasm` consumer has no local filesystem to resolve a relative path against.
- This package is stdlib-only (design constraint 2) and, per decision `001`, already scopes audio decode to WAVE PCM only — it has no Ogg/MP3/FLAC decoder and adding one is out of scope here for the same reason ADPCM was cut: no real fixture to validate a decoder against.

**Decision:**
1. **Detection is a payload heuristic, not a table-format flag.** `ParseV2` stays a cheap, blob-free parse (mirrors v1's own parse/decode split, `.vibe/index.md`). At decode time, `DecodeV2Sound` reads an entry's blob and classifies it as an external-file reference only if it is *not* a valid RIFF/WAVE blob *and* its bytes (after trimming one optional trailing NUL) are printable, non-empty, and end in a recognized audio extension (`.wav`, `.ogg`, `.mp3`, `.flac`, case-insensitive — the format's own examples plus the extensions Ikemen GO's audio stack elsewhere supports). Anything else that fails the RIFF/WAVE check is treated as v1 already treats it: a corrupt/malformed embedded entry, preserving that existing, real-corpus-validated error path (decision `001`'s "3 `not_riff_wave` entries" case) instead of silently reinterpreting garbage bytes as a bogus file path.
2. **Resolution goes through a caller-supplied opener, never this package's own I/O.** `DecodeV2Sound` takes an `ExternalAudioOpener func(path string) ([]byte, error)` parameter. When an entry resolves to a path, this package calls the opener and decodes whatever bytes come back — it never opens a file or makes a network call itself. A nil opener when an external reference is actually encountered, or an opener error, both return a descriptive error naming the entry and the path (never a panic or silent empty audio), per the item's own acceptance criteria.
3. **Only a WAV/PCM external payload actually decodes.** If the opener's returned bytes are valid RIFF/WAVE PCM, `DecodeV2Sound` decodes them exactly like an embedded entry (same `DecodedSound` shape, same PCM-only scope as decision `001`). Any other format — including a genuinely non-WAV `.ogg`/`.mp3`/`.flac` file, which this package has no decoder for — returns a descriptive "unsupported external audio format" error rather than attempting a decode this package cannot correctly perform.
4. **Validation gap accepted, mirroring `sff`'s decision `014`:** no real Ikemen GO character exercising this extension was found. `testdata/files/v2-external-ref.snd` is a clearly-marked, hand-built synthetic fixture (documented in `testdata/README.md`); the audio it ultimately resolves to (`testdata/files/v2-external-audio.wav`) is nonetheless real, unmodified sample data reused from the same corpus as every other fixture here, so only the *reference itself* — not the audio it points to — is synthetic. If a real character using this extension ever surfaces, it should replace this synthetic fixture, the same trigger condition `sff`'s decision `014` names for RLE5.

**Reason:** A caller-supplied opener is the only design that keeps this package usable from a browser WASM build (constraint 1) while still letting a native Go consumer resolve paths however it likes (relative to the `.snd` file, inside a bundled archive, from a preloaded map, ...) — exactly this project's existing "domain-independent, consumer decides its own I/O shape" posture (constraint 3). Scoping decode to WAV/PCM externals mirrors decision `001`'s own reasoning almost exactly: implementing a real Ogg/MP3/FLAC decoder validated only against hand-built synthetic bytes, for a feature with zero confirmed real usage, is the same unverifiable-speculative-code risk decision `001` already rejected for ADPCM.

**Rejected alternatives:**
- *Guess a specific binary flag/sentinel in the subheader's own bytes marking "this entry is external"* — rejected: decision `002` already shows the subheader's 16 bytes are fully accounted for (`next`+`length`+`group`+`sample`, no spare bits), and Ikemen GO's own loader reads every entry identically regardless of any such flag, so inventing one would be pure fabrication with nothing to validate it against.
- *Take a filesystem base directory and call `os.Open` directly* — rejected: breaks the WASM build target outright (constraint 1), and would still be wrong for a consumer whose assets live somewhere other than a directory (e.g. bundled inside a zip).
- *Add a pure-Go Ogg Vorbis/MP3 decoder to support real external playback formats* — rejected: violates the stdlib-only constraint (constraint 2) and cannot be validated against a real file either, compounding one unverifiable gap with another.
