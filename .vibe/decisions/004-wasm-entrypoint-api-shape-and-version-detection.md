# WASM entrypoint exposes one version-agnostic decode call; version detection uses the header's first version byte; external-file resolution is a synchronous JS callback

**Context:** Backlog item 003 asks for a `GOOS=js GOARCH=wasm` build exposing "a version-agnostic decode call (v1/v2 auto-detected, mirroring `sff.Load`'s own auto-detection) as a JS-callable global", mirroring sibling repo `sff`'s `cmd/wasm/` + release workflow shape. `sff.Load` auto-detects its own file format's version by peeking the shared header and checking one already-established version byte. `.snd` has no such version-agnostic function yet — only version-specific `ParseV1`/`DecodeV1Sound` and `ParseV2`/`DecodeV2Sound`.

**Decision:**
1. **A new root-package function, `DecodeSound(r io.ReaderAt, group, sample int, openExternal ExternalAudioOpener) (*DecodedSound, error)`**, peeks the file header, auto-detects v1 vs v2, and dispatches to the existing version-specific parse+decode pair. This is the function `cmd/wasm` exposes; it is also usable directly by a native Go caller who doesn't want to pick a version itself.
2. **Version detection checks `header[12]` (the first byte of the shared `Version [4]byte` header field), not the last one `sff.detectVersion` checks.** This is not a new guess: it is the exact byte this repo's own existing v2 test/fixture builders (`buildV2File` in `v2_test.go`, `testdata/gen/main.go`'s `2, 0, 0, 0` version stamp) already set to mark a file as v2, matching v1 fixtures' `1, ...` stamp at the same position. The two file formats lay out their version stamp differently on disk; the technique (peek the header, branch on an already-established byte) is the same as `sff.Load`'s.
3. **`cmd/wasm/main.go` exposes exactly one JS-callable global function**, `OpenKakutouSnd.decode(sndBytes, group, sample, resolveExternal)`, returning `{ sampleRate, channels, bitsPerSample, pcm, error }` (exactly one of `pcm`/`error` non-null) — mirroring `sff`'s `{ result, error }` shape and never-throws contract. `resolveExternal` is an optional JS function `(path) => Uint8Array`, invoked synchronously via `js.Value.Invoke` to resolve a v2 external-file-reference entry (see decision `003`'s `ExternalAudioOpener`); undefined/null means "no external references expected", matching `DecodeV2Sound`'s own nil-opener contract. Because the call is synchronous, `resolveExternal` cannot be backed by `fetch`/a Promise — the caller must already hold the external file's bytes (typically preloaded the same way it preloaded `sndBytes` itself) before calling `decode`. This is documented in the function's own doc comment and in `smoke.mjs`'s usage example, mirroring how `sff`'s own WASM entrypoint documents its synchronous contract.
4. Every exported WASM function recovers from panics per call (not only once in `main`), matching `sff`'s own `cmd/wasm/main.go` pattern, so one malformed call can never tear down the shared long-lived WASM instance a consumer like `mode-quick-versus` keeps alive for a whole session.

**Reason:** A single `decode` call matches the acceptance criteria's own wording ("a version-agnostic decode call", singular) and keeps the JS surface as small as `sff`'s own two-function surface is proportionate to its own two operations (`load`, `resolveSprites`) — `.snd` only has one operation (decode a sound), so it gets one call. Checking `header[12]` rather than reinventing a new detection scheme reuses this repo's own already-validated convention instead of fabricating a new one. A synchronous external-file callback is the only shape that keeps this package's no-filesystem/no-network-I/O-of-its-own guarantee (`CLAUDE.md` design constraint 1) intact at the WASM boundary, exactly as decision `003` already established at the Go-API boundary for the same reason.

**Rejected alternatives:**
- *Expose separate `decodeV1`/`decodeV2` JS functions, leaving version detection to the JS caller* — rejected: defeats the acceptance criteria's explicit requirement for one version-agnostic call, and pushes work back onto every JS consumer that `sff.Load`'s own precedent already shows belongs in the library.
- *Mirror `sff.detectVersion`'s exact byte offset (the version field's last byte) for consistency across repos* — rejected: would silently misdetect every real `.snd` file, since this repo's own existing v1/v2 fixtures and generator already establish the first byte as the discriminating one for this format; consistency with `sff`'s offset would be consistency with the wrong value.
- *Make `resolveExternal` async (return a Promise, awaited via a JS trampoline)* — rejected: `syscall/js` calls into JS are synchronous by construction from the Go side within one exported function invocation; supporting a Promise would require restructuring `decode` around a callback/promise pattern for every call, including the common case with no external references at all, for a feature (`003`'s extension) with no confirmed real-world usage yet (see decision `003`'s own accepted validation gap).
