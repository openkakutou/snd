## Modules
- [`modules/root.md`](modules/root.md) — package `snd`: `.snd` v1 and v2 read paths — header/sound table parsing (`ParseV1`/`ParseV2`) and PCM decode (`DecodeV1Sound`/`DecodeV2Sound`), keyed by `(group, sample)`; v2 also resolves Ikemen GO's external-file-reference extension; `DecodeSound` (backlog item 003) auto-detects v1 vs v2 itself, so a caller — including `cmd/wasm` — never has to choose a version-specific function
- [`modules/wasm.md`](modules/wasm.md) — `cmd/wasm`, this repo's own WebAssembly entrypoint (backlog item 003): build-tag-gated `syscall/js` glue exposing `DecodeSound` as a single JS-callable global (`OpenKakutouSnd.decode`), built and released independently of `character`'s own WASM build, verified by a Node.js smoke harness since `syscall/js` code cannot run under the plain Go toolchain

## Observed patterns
- Read path is split into a cheap parse step (`ParseV1`/`ParseV2`, locates each sound's offset/length without reading its audio) and a decode step (`DecodeV1Sound`/`DecodeV2Sound`, reads and decodes one entry's audio on demand) — mirrors `sff`'s own parse/resolve separation
- Errors always name the offending `(group, sample)` entry (and an external file's path, for v2) and wrap the underlying cause with `%w`; malformed input never panics
- `DecodeV1Sound`/`DecodeV2Sound` only decode WAVE format tag 1 (PCM), 8-bit unsigned or 16-bit signed — ADPCM is a permanent, documented scope cut (see `decisions/001`), backed by a corpus scan (496 real files, 54,306 sound entries, 0 ADPCM) and by Ikemen GO's own reference sound loader also only accepting PCM
- 8-bit PCM is re-centered around zero and scaled to the full 16-bit range on decode; `DecodedSound.PCM` is always signed 16-bit regardless of source depth, shared unchanged between v1 and v2 decode
- v1 and v2 subheaders are byte-for-byte identical: both read `Group`/`Sample` as 4-byte fields filling the whole subheader, matching Ikemen GO's own reference loader (see `decisions/002` and `decisions/005`) — v1 originally shipped reading them as 2-byte fields (4 bytes left unread), a corpus-scale-confirmed bug (99.8% of real files, 72% of entries affected) fixed under backlog item `004`
- A v2 entry's payload is classified as an external-file-reference (Ikemen GO's own extension) by a payload heuristic at decode time, not a table-format flag: not a valid RIFF/WAVE blob, but printable and ending in a recognized audio extension (`.wav`/`.ogg`/`.mp3`/`.flac`); anything else that fails the RIFF/WAVE check is still treated as v1-style corrupt embedded data (see `decisions/003`)
- Resolving an external reference goes through a caller-supplied `ExternalAudioOpener` callback, never this package's own I/O — keeps the package WASM-safe and consumer-agnostic; only a WAV/PCM external payload actually decodes, matching the existing PCM-only decode scope
- `decodeWAVPCM`'s RIFF/WAVE parsing core (`decodeWAVPCMWithContext`) is shared between v1's embedded decode, v2's embedded decode, and v2's resolved-external decode, each supplying its own error-message context string, rather than being duplicated per call site
- Decoders are validated against real, unmodified community `.snd` files trimmed into `testdata/files/` via `testdata/gen` (mirrors `sff`'s own trimming-tool pattern), with v1's expected values independently derived via Python's `wave` module rather than this package's own decoder; no real file in the corpus declares itself `.snd` v2 or uses the external-file-reference extension, so those two gaps are accepted and clearly marked (mirroring `sff`'s own accepted-gap precedent for RLE5, its decision `014`) rather than left unimplemented
- `DecodeSound` auto-detects v1 vs v2 by peeking `header[12]` (the first byte of the shared `Version [4]byte` field) — `2` means v2, matching the exact stamp this repo's own v2 test/fixture builders already write; this mirrors `sff.Load`'s own peek-the-header auto-detection technique, but at a different byte offset, since the two formats lay their version stamps out differently on disk
- `cmd/wasm` is the one package gated by a Go build constraint (`//go:build js && wasm`) rather than by directory convention alone, keeping `syscall/js`-only code out of a normal host `go build ./...`/`go test ./...`; its own correctness is instead verified by a Node.js script (`smoke.mjs`) loading the built module the way a real browser would. `.snd` exposes exactly one JS-callable global (`OpenKakutouSnd.decode`) — unlike `sff`'s two-operation surface — since decoding a sound is this package's one operation; a v2 external-file-reference is resolved through a JS callback invoked synchronously from Go (`js.Value.Invoke`), so it cannot be backed by `fetch`/a Promise, mirroring `ExternalAudioOpener`'s own synchronous, caller-supplied-I/O contract at the Go API level. The tagged-release workflow (`.github/workflows/release.yml`) gates publishing the built `snd.wasm`/`wasm_exec.js` pair on that same smoke test passing against the exact built artifact, not just a successful native build — see `.vibe/decisions/004-wasm-entrypoint-api-shape-and-version-detection.md`.
